# 液量、砂量与缝长误差口径

## 1. 液量误差为什么接近零

当前光纤累计液量分配直接作为 PKN 的分簇入流边界：

\[
q_i(t)=Q(t)\,a_i^{liq}(t),\qquad
a_i^{liq}(t)=\frac{\Delta V_{liq,i}(t)}{\sum_j\Delta V_{liq,j}(t)}.
\]

因此模型输出的液量份额与输入边界是同一个量，液量 TVD 接近机器精度零。这不是“模型独立预测液量达到零误差”，而是对数据接入、归一化和守恒的校验。液量的独立验证需要把一段光纤数据留出，不将其作为 PKN 入流边界。

## 2. 砂量误差的计算与改进

砂量没有直接作为 PKN 流量边界，而是通过简化携砂容量代理预测：

\[
c_i(t)=q_{i,eff}(t)\,w_i(t),
\]

并用累计记忆计算累计输运能力：

\[
M_i(t_k)=M_i(t_{k-1})+\Delta t\,c_i(t_k).
\]

原始的线性代理会将高排量、高缝宽簇的砂量过度集中。当前版本增加守恒的次线性修正：

\[
\tilde c_i=c_i\left(\frac{c_i}{\bar c}\right)^{\gamma-1},\qquad \gamma=0.75.
\]

\(\gamma<1\) 表示混砂、沉降、簇间再分配等效应使携砂能力对局部水力能力不是完全线性响应；它不属于 EnKF 隐藏状态，也不直接修改缝长。正式第 8 段 70%校准、30%留出结果中，砂量分配 TVD 从 24.44% 降到 13.67%，井底压力相对误差约 5.41%，液量边界一致性保持 0%。

这仍是降阶输运代理，不是颗粒两相流求解器。进一步降低砂量误差需要真实砂浓度、簇内携砂/沉降或 DAS 事件标注，用于校准输运系数。

## 3. 缝长误差为什么改用液量的 0.6 次幂

当前 PKN 长度关系中，分簇长度对分簇排量的主要尺度关系为：

\[
L_i\propto q_i^{0.6}t^{0.8}.
\]

此前将总后验长度按“0.7液量份额+0.3砂量份额”线性分配，与 PKN 的 \(q^{0.6}\) 关系不一致，会把簇间长度差异人为放大。当前缓存改为：

\[
\hat L_i=L_{total}\frac{(a_i^{liq})^{0.6}}
{\sum_j(a_j^{liq})^{0.6}},
\qquad
e_L=\frac{\sum_i|L_i-\hat L_i|}{\sum_i\hat L_i}.
\]

这是“PKN 一致的等效水力估计”，不是独立裂缝半长真值。当前缓存的全程平均缝长误差约 0.40%，P95 约 1.47%，最大约 2.04%；同时所有簇长度没有超过 5% 的单步回缩。

砂量不会直接混入缝长分配，因为砂量是支撑剂输运通道，液量才是 PKN 水力扩展的入流边界。将两者直接线性混合会重复计算砂量对水力长度的影响，并可能重新制造缝长跳变。

## 4. 计算时间与误差的关系

正式版本平均单步约 421 ms，P95 约 437 ms，显著低于 15 s 上限。15 s 是最大在线延迟约束，不是要求把计算做慢。当前误差主要由观测算子和物理简化引起，而不是计算量不足；增加集合规模只能改善统计稳定性，不能替代真实颗粒输运和独立裂缝几何观测。
