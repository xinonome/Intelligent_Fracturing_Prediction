# 智能压裂项目数据管线计算细节与甲方审查清单

## 1. 文档目的

本文按当前代码的真实调用链解释数据如何进入模型、经过哪些计算、EnKF 实际更新什么，以及结果如何进入智能体。本文不是概念方案，而是供甲方专业人员检查字段、单位、公式和物理假设的代码审查底稿。

必须区分三条链路：

1. **第二部分正式验证链**：`run_project.py dt validate`，EnKF 更新 PKN 物理参数、分簇进液参数和分簇携砂参数。这是当前主要验收链路。
2. **第二部分旧展示链**：`inversion/playback.py`，EnKF 只更新每簇有效生长系数，并未更新全部全局物理参数。它没有直接覆盖缝长，但成熟度低于正式验证链。
3. **第三部分训练仿真链**：`HMI-KE/rl/digital_twin_env.py`，EnKF 更新物理参数，但观测由隐藏“真值状态”合成，用于强化学习训练，不能作为现场反演精度证明。

## 2. 总体数据流

```text
Data/raw_frac 压裂秒点
  -> 按 FDBH 分段并按时间排序
  -> 300 s 历史窗口特征
  -> 工况分类概率、强化学习状态

Data/3Dfrac/光纤本井监测08.txt
  -> 分簇液量、砂量、累计液量、累计砂量、均衡程度
  -> 统一成逐时刻逐簇 controls
  -> 作为 EnKF 观测，而不是直接作为 PKN 分簇输入

Data/3Dfrac/JY84-Z1-stage08-f1.xls
  -> 施工压力、累计液量、砂比
  -> 井口压力换算井底压力和净压力
  -> 作为 EnKF 压力观测

总排量 + PKN 参数集合
  -> PKN/Carter 正演
  -> 预测分簇液量占比、砂量占比、井底压力
  -> 与现场观测计算残差
  -> EnKF 更新参数集合
  -> 用更新后的参数重新运行 PKN
  -> 得到后验裂缝几何和压力

后验状态 + 工况概率
  -> Gymnasium 环境
  -> PPO/SAC 输出未来 60 s 排量和砂比建议
  -> 动作约束、数字孪生响应、奖励、安全判断
```

## 3. 第一部分：压裂秒点与工况模型

### 3.1 数据整理

`FSL-Expert/frac_gnn/data.py` 从 `Data/raw_frac` 读取 Excel/CSV，使用总表表头修复无表头分段表。若单文件包含多个 `FDBH`，按 `FDBH` 分组；每段内部按时间列排序。

标签列为 `WORKING_TYPE`。空标签通过标签归一化逻辑视为“正常”。时间、井号、段号、备注、结果性字段不作为模型特征。主要工艺特征包括施工泵压 `SGBY`、排量 `PL`、砂比 `SB`、黏度及其滚动统计量。

数据按段划分，防止同一段的相邻秒点同时进入训练集和测试集。窗口只能在单段内生成。

### 3.2 两阶段工况识别

第一层计算：

```text
P(异常 | x)
```

第二层仅对第一层判定为异常的样本计算：

```text
P(砂堵/缝口暂堵/缝内暂堵/其他异常 | 异常, x)
```

最终概率是条件概率乘积，例如：

```text
P(砂堵 | x) = P(异常 | x) * P(砂堵 | 异常, x)
```

若第一层异常概率为 `0.30`，第二层砂堵条件概率为 `0.60`，最终砂堵概率应为 `0.18`，不能直接报告为 `0.60`。

### 3.3 需要甲方确认

- `SGBY` 是施工泵压还是其他泵业字段，单位是否统一为 MPa。
- `PL` 是否始终为 m3/min，`SB` 是百分数还是 kg/m3。
- 空白 `WORKING_TYPE` 是否在所有时期都确实代表正常，而非漏标。
- 工况标签是点级标签还是事件区间标签，边界前后是否需要容忍窗口。

## 4. 第二部分：真实数据接入和压力换算

### 4.1 光纤分簇数据

`stage_info_to_controls()` 输出每个时刻、每个簇：

```text
cluster_id
liquid_volume_m3
sand_mass_t
cumulative_liquid_volume_m3
cumulative_sand_mass_t
balance_degree
cumulative_balance_degree
flow_rate_m3_min
allocation_weight
```

若瞬时液量为空而累计液量存在，则按同一簇累计量差分恢复瞬时量：

```text
delta_V_i(t) = max(Vcum_i(t) - Vcum_i(t-1), 0)
Q_i(t) = delta_V_i(t) / delta_t * 60
```

`allocation_weight = delta_V_i / sum(delta_V)`。需要确认原始 `jyl/jsl` 是本时间步增量还是从开始累计值，否则可能重复差分或重复累计。

### 4.2 施工压力转井底压力

当前代码使用：

```text
rho_slurry = rho_fluid * (1 - sand_fraction) + rho_sand * sand_fraction
P_hydrostatic = rho_slurry * g * TVD / 1e6
P_bh = P_surface + P_hydrostatic - P_pipe_friction - P_perf_friction
P_net_raw = P_bh - sigma_min
P_net = max(P_net_raw, 0)
```

沿程摩阻：

```text
P_pipe = fcd * 1.385e6 * dwell^(-4.8) * Q^(1.6) * MD * mzl / 1e6
```

孔眼摩阻：

```text
P_perf = 0.8081e-6 * rho_sand * Q^2 /
         (N_perf^2 * d_perf^4 * C_d^2)
```

当前默认 `48` 孔、孔径 `10 mm`、流量系数 `0.85`。`fcd=1e-10`、井筒内径、冲蚀系数等仍是可运行占位值，未经过现场标定。

### 4.3 压力数值例子

假设施工压力 `55 MPa`、砂比 `10%`、TVD `3196.94 m`、基液密度 `1000 kg/m3`、支撑剂密度 `2650 kg/m3`：

```text
rho_slurry = 1000 * 0.9 + 2650 * 0.1 = 1165 kg/m3
P_hydrostatic = 1165 * 9.80665 * 3196.94 / 1e6 = 36.52 MPa
```

若沿程摩阻 `12 MPa`、孔眼摩阻 `3 MPa`：

```text
P_bh = 55 + 36.52 - 12 - 3 = 76.52 MPa
```

若最小水平主应力 `60 MPa`：

```text
P_net = 76.52 - 60 = 16.52 MPa
```

甲方应重点核对砂比参与密度计算的方式。若 `SB=10` 代表 kg/m3 而不是 10%，上述计算会严重偏高。

## 5. PKN 正演计算

### 5.1 EnKF 状态向量

正式验证链的状态不是缝长，而是：

```text
x = [log(E'/E0), log(CL/CL0), log(mu/mu0), sigma_min,
     f1...f6, s1...s6]
```

- `E'`：平面应变模量。
- `CL`：Carter 滤失系数。
- `mu`：流体黏度。
- `sigma_min`：最小水平主应力。
- `fi`：第 i 簇动态进液/生长参数。
- `si`：第 i 簇携砂输运参数。

使用对数比例保存前三个正参数，避免更新后出现负模量、负滤失或负黏度。

### 5.2 分簇排量

正式链故意不给 PKN 输入真实分簇液量占比，以避免“把答案输入模型再拿同一答案验证”。输入只使用总累计液量和总当前排量，并在六簇间均分：

```text
Q_history_total = cumulative_liquid_total / elapsed_time
q_base_i = Q_history_total / 6
q_current_i = Q_current_total / 6
```

分簇差异由待反演参数 `fi` 和水力耦合共同产生。

### 5.3 PKN/Carter 计算

基础半长关系：

```text
L_i = 0.68 * ((q_eff_i^3 * E') / (mu * H^4))^0.2 * t^0.8
```

随后计算裂缝面积和 Carter 滤失：

```text
A_i = 4 * L_i * H
V_leak_i = 2 * CL * A_i * sqrt(t)
q_eff_i = max(q_nominal_i - V_leak_i/t, 0.05*q_nominal_i)
```

代码迭代六次，使缝长、滤失和有效排量相互一致。滤失总量被限制在累计注入量的 `85%` 以内。

开度关系：

```text
w_i = 2.5 * ((q_current_eff_i^3 * mu)/(E' * H^3))^0.2 * t^0.2
```

压力代理：

```text
P_net = pressure_scale * E' * mean(w_i/2) / H / 1e6
P_bh = sigma_min + P_net
```

这里的 `pressure_scale=30` 是工程代理标度，并非严格 PKN 压力解析式，是当前模型最需要专业审查的部分之一。

## 6. 观测算子：模型输出如何与现场数据比较

正式链不把“等效缝长”作为主要观测，而直接比较可观测量：

```text
现场观测 y = [前5簇累计液量占比,
              前5簇累计砂量占比,
              井底压力]
```

第 6 簇占比由总和为 1 隐含，删除它可以避免协方差矩阵严格线性相关。

模型预测液量占比：

```text
liquid_share_i = q_eff_i / sum(q_eff)
```

模型预测砂量占比采用简化携砂能力代理：

```text
sand_capacity_i = q_eff_i * aperture_i * s_i
sand_share_i = sand_capacity_i / sum(sand_capacity)
```

这是 reduced-order 观测算子，不是完整支撑剂运移方程。甲方需判断 `q*w` 是否足够，或是否应加入沉降速度、临界携砂流速、砂浓度、簇口冲蚀等项。

旧展示链还保留另一种等效缝长观测：

```text
activity_i = 0.70*cumulative_liquid_score_i
           + 0.30*cumulative_sand_score_i
factor_i = clip(1 + (activity_i-1)*(1+0.2*imbalance), 0.85, 1.15)
L_obs_i = L_prior_i * factor_i
```

该观测依赖 `L_prior`，存在一定循环性，因此只能用于展示，不应作为真实缝长精度验收依据。

## 7. EnKF 到底更新了什么

### 7.1 数学步骤

对集合中第 j 个参数状态 `x_j`，先运行 PKN 和观测算子得到 `y_j=h(F(x_j,u))`。

```text
Pxy = covariance(X, Y)
Pyy = covariance(Y, Y) + R
K   = Pxy * inverse(Pyy)
x_j_post = x_j_prior + K * (y_obs + epsilon_j - y_j_prior)
```

更新后执行参数边界裁剪，然后再次运行 PKN：

```text
geometry_post = PKN(x_post, controls)
```

代码中不存在：

```text
L_post = L_prior + K * (L_obs - L_prior)
```

也不存在将 `observed_half_length_m` 直接赋值给最终缝长的操作。正式链后验缝长只能由更新后的 `E'、CL、mu、sigma_min、fi` 重新正演得到。

### 7.2 当前真实运行实例

正式结果首个同化点记录如下：

| 参数/指标 | 更新前 | 更新后 |
|---|---:|---:|
| E' | 32.924 GPa | 34.580 GPa |
| CL | 1.0360e-5 | 1.0359e-5 m/s^0.5 |
| mu | 0.10013 | 0.10402 Pa.s |
| sigma_min | 58.741 | 67.367 MPa |
| 簇1因子 | 1.0023 | 1.0322 |
| 簇4因子 | 0.9807 | 0.9075 |
| 井底压力 | 58.741 | 67.367 MPa |
| 井底压力观测 | 75.162 | 75.162 MPa |
| 压力相对误差 | 21.85% | 10.37% |

这说明残差没有直接改写井底压力或缝长，而是主要推动 `sigma_min` 从 `58.741` 更新到 `67.367 MPa`，并同时调整其他参数；随后 PKN 重新计算得到 `67.367 MPa` 的后验压力。

但这个实例也暴露问题：首点使用 `t=1 s`，后验缝长只有约 `10^-5 m`，滤失比例达到 `0.85` 上限。甲方需要确认光纤 `step=0` 是否应解释为施工开始后的 1 秒，还是应映射到该阶段真实累计施工时间。

## 8. 第三部分：强化学习数据流

### 8.1 状态构造

`HMI-KE/data_pipeline.py` 在同一段内取当前之前 300 个秒点。默认每个状态列保留完整窗口，并补充：

```text
末值、均值、标准差、线性斜率
```

若状态列为压力、排量、砂比，则单列有 `300+4` 个特征。环境再拼接后验缝长、EnKF 误差、井底/净压力、异常概率、砂堵概率及当前控制量。

### 8.2 动作

策略输出 `a=[a_Q,a_SB]`，范围 `[-1,1]`。动作不是绝对物理值，而是映射到当前值附近的安全区间：

```text
Q_next in [Q_current-max_delta_Q, Q_current+max_delta_Q]
SB_next in [SB_current-max_delta_SB, SB_current+max_delta_SB]
```

再经过最大排量、最大砂比、单步增量和连续/间隔加砂规则裁剪。每个动作代表未来 `60 s` 的排量和砂比建议。

### 8.3 数字孪生响应

动作进入 `DigitalTwinFracturingControlEnv` 后：

1. 更新累计注入量。
2. 计算历史等效排量和当前排量。
3. 对参数集合加入过程噪声。
4. 每个集合成员运行 PKN。
5. 用合成隐藏真值产生缝长和压力观测。
6. EnKF 更新参数。
7. 用后验参数重新运行 PKN。
8. 计算异常概率、砂堵概率和奖励。

这里的观测是仿真观测：

```text
L_obs = PKN(x_truth) + noise
P_bh_obs = 0.65*PKN_pressure(x_truth) + 0.35*historical_pressure + noise
```

因此第三部分当前验证的是“策略在数字孪生仿真器中的学习能力”，不是现场在线控制效果。

### 8.4 奖励

```text
reward = effectiveness
       - pressure_penalty
       - abnormal_penalty
       - construction_cost
       + schedule_reward
```

效果项由后验总缝长增量和 EnKF 后验误差组成；压力项约束井底压力 `45-110 MPa` 和净压力 `0-35 MPa`；风险项使用异常和砂堵概率；成本项惩罚高排量、高砂比和大幅动作变化。

当前权重为效果 `3`、压力 `3`、异常风险 `4`、施工成本 `1`。这些权重是算法配置，不是已获得甲方确认的经济价值函数。

## 9. 当前必须由甲方审查的高风险细节

1. **时间基准**：光纤 `step` 是否是真实累计秒数；当前首点 `t=1 s` 明显可疑。
2. **压力列映射**：XLS 第 10 列是否始终为施工压力，列 11、12、13 的含义和单位是否固定。
3. **砂比单位**：百分比、kg/m3 和质量分数不可混用。
4. **摩阻标定**：`fcd`、内径、MD、孔眼流量系数和冲蚀系数需要现场值。
5. **最小水平主应力**：初值 60 MPa 和允许范围 35-90 MPa 是否符合该井段。
6. **PKN 适用条件**：固定缝高 30 m、平面应变、裂缝间应力阴影简化是否可接受。
7. **压力代理式**：`pressure_scale=30` 是否有物理或标定依据。
8. **滤失上限**：当前部分时刻触及 85% 上限，可能掩盖单位或时间错误。
9. **砂输运算子**：`q_eff*w*s_i` 是否需要替换为更完整的支撑剂运移模型。
10. **参数可辨识性**：仅凭分簇占比和井底压力，同时反演 E'、CL、mu、应力和 12 个簇参数可能存在多解。
11. **验证口径**：当前 15% 指标是液量占比 TVD、砂量占比 TVD、井底压力相对误差，不是真实缝长误差。
12. **智能体观测**：第三部分使用合成真值，必须在报告中标为仿真训练，不得描述为真实闭环控制。

有了这一组人工核算基准，才能对管线建立单元级“金标准测试”，避免模型最终指标正常但中间物理计算错误。
